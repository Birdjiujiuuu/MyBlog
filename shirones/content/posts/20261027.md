Shirone 是一个基于 Astro 7 的二次元风格静态博客主题，对新手相当友好。它提供源码模板和 npm 包两种使用方式。如果你只想快速拥有一个能写文章、能换外观的博客，而不打算折腾主题内部代码，**npm 包模式是更省心的选择**。

本教程基于 Shirone 的 npm 包模式，记录了搭建个人网站的过程。也可以前往 [`官方文档`](https://docs.shirone.mysqil.com/guide/intro/) ，查看更加详细的网站部署教程。



## 准备工作

- Node.js >= v26.13.0（或在 Shirone 的官方文档确认最新版所要求的版本）
- pnpm 11.28.2（若未安装 pnpm，执行 `npm install -g pnpm@11.28.2`）

## 第一步：初始化项目

Shirone 的 npm 模式通过 `npx shirones init` 完成初始化。在希望作为网站内容存放的空文件夹开启终端，并运行：

```bash
npx shirones init
pnpm dev
```

此时应该能够完成初始化，并且在本地启动网站，在浏览器打开 `http://localhost:4321/` 即可进入站点。

## 第二步：配置站点信息

打开 `shirones/config/siteConfig.ts`，至少修改以下几项：

```ts
import type { SiteConfig } from "@/types/config";

export const siteConfig: SiteConfig = {
  site: "https://example.com/",
  title: "我的博客",
  // 其他配置按需修改……
};
```

`site` 是最关键的字段，它会影响站点地图、RSS、Open Graph 等生成结果。部署前一定要改成你的真实网址。如果你部署在 GitHub Pages 的**项目站点**（`username.github.io/repo-name`），还需要设置 `base` 为 `/repo-name/`，否则静态资源路径会 404。

## 第三步：撰写文章

文章放在 `shirones/content/posts/` 下，可以是 `.md` 或 `.mdx`。Shirone 初始化会生成示例文章，可供参考，也可以在官方文档学习更多文章编写的技巧。

## 第四步：构建生产版本

部署前，先在本地确认构建能通过：

```bash
npm run build
```

构建成功后，静态文件生成在 `dist/` 目录，可以用 `npm run preview` 快速检查构建后的效果。

## 第五步：部署到网站托管平台

### GitHub Pages

GitHub Pages 是零成本的静态托管选择，适合个人博客。

#### 1. 仓库与 Astro 配置

把项目推送到 GitHub 仓库前，注意 `site` 和 `base` 的配置：

- **用户/组织站点**（仓库名必须为 `username.github.io`）：发布在 `https://username.github.io/`，`base` 通常留空。
- **项目站点**（仓库名如 `my-blog`）：发布在 `https://username.github.io/my-blog/`，`base` 必须设为 `/my-blog/`，否则图片、CSS 等资源会 404。

#### 2. 创建工作流

在项目根目录创建 `.github/workflows/deploy.yml`，粘贴以下内容：

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 11.28.2

      - uses: actions/setup-node@v4
        with:
          node-version: 26
          cache: pnpm

      - run: pnpm install --frozen-lockfile
      - run: pnpm build

      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

`node-version: 26` 与 `pnpm/action-setup` 步骤均不可省略，GitHub Actions Runner 默认的 Node.js 版本不符合主题最低要求。

#### 3. 启用 Pages

- 进入 GitHub 仓库的 **Settings → Pages**；
- 在 **Build and deployment** 下，把 **Source** 改为 **“GitHub Actions”**，无需选择分支，保存即可；
- 之后向 `main` 分支推送代码，工作流会自动构建并部署。
首次部署完成后，Pages 页面会显示站点 URL。

#### 4. 绑定子域名（如 `blog.example.com`）

**第 1 步：在 DNS 服务商添加 CNAME 记录**

| 类型 | 主机记录 | 记录值 |
|---|---|---|
| CNAME | `blog` | `username.github.io` |

**第 2 步：在 GitHub 仓库中设置 Custom domain**

进入 **Settings → Pages**，在 “Custom domain” 中填入 `blog.example.com`，保存。DNS 生效后勾选 **Enforce HTTPS**。

**第 3 步：CNAME 文件**

设置完域名后，GitHub 会在根目录生成 `CNAME` 文件；也可以手动在根目录中放一个 `CNAME` 文件。

#### 5. 绑定 apex 域名（如 `example.com`）

根域名不能使用 CNAME，需要在 DNS 服务商添加 GitHub 官方的 A 记录（以 GitHub 官方文档的最新列表为准）：

```text
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
```

添加 4 条 A 记录，主机记录填 `@`，然后在 GitHub Settings → Pages 中填入 `example.com`，等待 DNS 生效并勾选 HTTPS。

### Cloudflare Pages

Cloudflare Pages 的免费额度、全球 CDN 和自动 HTTPS 对个人博客很友好，绑定域名的流程也比 GitHub Pages 更直观。

#### 1. 连接 Git 仓库

登录 Cloudflare Dashboard，进入 **Workers & Pages → Create → Pages → Connect to Git**，选择在 Github 上传的博客仓库。构建设置填写：

| 设置项 | 值 |
|---|---|
| 框架预设 | Astro |
| 构建命令 | `pnpm build` |
| 构建输出目录 | `dist` |

保存后 Cloudflare 会自动拉取代码、执行构建，并分配一个 `*.pages.dev` 临时域名。

#### 2. 绑定子域名（如 `blog.example.com`）

进入 Pages 项目 → **Custom domains → Set up a domain**，输入 `blog.example.com`。

- 如果域名的 DNS 已托管在 Cloudflare，CNAME 记录通常会自动创建。
- 如果 DNS 在其他服务商，手动添加：

| 类型 | 名称 | 内容 |
|---|---|---|
| CNAME | `blog` | `<你的项目名>.pages.dev` |

#### 3. 绑定 apex 域名（如 `example.com`）

Cloudflare Pages 要求 apex 域名必须已经作为 Cloudflare zone 托管在同一账户下。也就是说，你需要把域名的 nameserver 改为 Cloudflare 提供的 nameserver，让 Cloudflare 接管 DNS 解析，然后 Pages 才能为 apex 域名自动创建记录。如果域名已经托管在 Cloudflare，直接在 Custom domains 中输入 apex 域名并确认即可。

绑定完成后，Cloudflare 会自动签发 SSL 证书，稍等片刻即可用自定义域名访问博客。

---

至此，你已经成功使用 Shirone 的 npm 模式完成了个人博客的搭建。接下来只需要根据官方文档自定义博客内容并撰写文章，在主题升级时执行一次 `npx shirones init --update` 即可，已有的文章内容不会被覆盖。
